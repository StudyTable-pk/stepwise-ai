Build the complete production-ready StepWise AI application.StepWise is an AI-powered learning environment where the STUDENT BOARD is the primary workspace.The product must not behave like a normal chatbot.The central experience is:QUESTION↓AI INTRODUCTION↓INTERACTIVE BOARD↓STUDENT THINKS / WRITES / SPEAKS / DRAWS↓AI OBSERVES↓AI DETECTS MEANING, ERRORS AND MISSING CONCEPTS↓AI HINTS / GUIDES / VISUALIZES↓STUDENT CORRECTS↓AI VALIDATES↓NEXT STEP↓FINAL UNDERSTANDING↓FINAL REPORT↓LEARNING JOURNEY UPDATE↓PERSONALIZED NEXT LEARNINGThe system must support children, teenagers, university students and adult learners through one adaptive product.==================================================PART 1 — PRODUCT ARCHITECTURE==================================================Build the application as a modular system.Core modules:1. Authentication2. User Profile3. Onboarding4. Home Dashboard5. Question Input6. AI Session Engine7. Interactive Board8. Text Input9. Handwriting Input10. Voice Input11. Drawing/Input Tools12. AI Analysis13. Teaching Engine14. Visual Learning Engine15. Analyze Board16. Session State17. Final Report18. Learning Journey19. Concept Graph20. Mastery System21. Misconception System22. Prerequisite System23. Review System24. Search25. Saved Boards26. Settings27. Accessibility28. Subscription/billing architecture if later required29. Admin/monitoring infrastructureKeep modules independent enough that they can be updated without rewriting the entire application.==================================================PART 2 — APPLICATION STRUCTURE==================================================Create a clean structure similar to:/app    /auth    /onboarding    /home    /learn    /board    /journey    /reports    /settings/components    /board    /ai    /visuals    /navigation    /reports    /journey/lib    /ai    /database    /auth    /voice    /storage    /analytics    /security/api    /auth    /sessions    /board    /ai    /reports    /journey    /searchDo not tightly couple UI components to database implementation.==================================================PART 3 — TECHNOLOGY DECISIONS==================================================If the generation environment already provides a preferred production stack, use its supported stack rather than introducing unnecessary dependencies.Otherwise prefer:Frontend:React / Next.jsLanguage:TypeScriptStyling:Tailwind CSS or managed realtime service where necessaryDo NOT hard-code the application around one AI provider.==================================================PART 4 — AI PROVIDER ABSTRACTION==================================================Create an AI service abstraction.Example conceptual rest of the application should call these services rather than directly calling a specific AI provider.This allows future model changes.==================================================PART 5 — image/handwriting understanding:vision-capable modelSpeech:speech-to-text modelVisual generation:diagram/visual generation systemFinal synthesis:language modelDo not use an expensive model for every tiny interaction.Use the least expensive capable model where appropriate.==================================================PART 6 — API SECURITY==================================================NEVER expose private AI provider API keys in frontend code.All secret API credentials must remain server-side.Frontend requests:Client↓Authenticated backend↓AI service↓ResponseNever:Client↓AI provider directly with secret key==================================================PART 7 — ENVIRONMENT
