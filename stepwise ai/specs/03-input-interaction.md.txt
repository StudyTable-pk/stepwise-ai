STEPWISE AIPROMPT 03 — INPUT, HANDWRITING, VOICE, IMAGE & CONTENT RECOGNITION ENGINEBuild a unified input and recognition system for StepWise AI.The student must be able to communicate with the AI naturally through the Board.The system must understand that a student's input is not always a perfect sentence.A student may:- Type- Handwrite- Speak- Draw- Upload an image- Paste text- Write equations- Mix multiple input methods- Use incomplete sentences- Use informal language- Use different languagesThe purpose of this engine is to convert all of these forms of communication into meaningful structured information that the StepWise AI reasoning engine can understand.---1. UNIFIED INPUT PRINCIPLEAll input methods must ultimately feed into the same AI understanding system.The system should not treat:«typed answer»«handwritten answer»«spoken answer»as three completely different learning experiences.They are different ways of expressing the student's thinking.The AI must try to understand the underlying meaning regardless of input method.---2. TEXT INPUTProvide a simple text tool on the Board.When selected, the student can click/tap anywhere and start typing.Support:- Normal text- Paragraphs- Short answers- Lists- Notes- Questions- Definitions- Explanations- Comparisons- Mathematical notation where possibleTyped text should become a movable Board object.---3. TEXT OBJECT BEHAVIOREvery student-created text block should have:- Unique ID- Position- Size- Content- Creation time- Last modified time- Associated question/session- Student-owned statusThe AI should be able to reference individual text blocks.Example:Text Block #17«Plants use sunlight to make food.»AI can associate this object with:- Photosynthesis- Sunlight- Food production---4. FREEFORM TEXTDo not force students to write in a predefined answer box.They should be able to place multiple text blocks anywhere.Example:Plants need sunlight.              CO₂Plants make glucose.       Oxygen is released.The AI should treat these as related ideas when appropriate.---5. HANDWRITING INPUTProvide a dedicated handwriting tool.The student can write naturally using:- Finger- Stylus- MouseSupport:- Pen- Pencil- Highlighter- Eraser- Lasso selection- Undo- RedoHandwriting should remain visible on the Board.---6. HANDWRITING UNDERSTANDINGThe AI system should attempt to recognize:- Letters- Words- Numbers- Mathematical symbols- Fractions- Exponents- Roots- Equations- Arrows- Labels- Basic diagramsRecognition should not require perfect handwriting.If recognition confidence is low, do not silently convert the student's work into incorrect text.Instead, ask for clarification.---7. HANDWRITING + ORIGINAL STROKESPreserve the original handwriting strokes.Even if the system converts handwriting to text internally, the student's original visual work must remain available.This allows:- visual authenticity- correction- undo- AI interpretation- future recognition improvements---8. HANDWRITING RECOGNITION CONFIDENCEEvery recognized handwritten element should have an internal confidence score.Example:Recognized:"photosynthesis"Confidence:96%If confidence is high:Continue normally.If medium:Use contextual reasoning.If low:Ask the student.Never confidently mark a student wrong because handwriting recognition was uncertain.---9. MATHEMATICAL HANDWRITINGFor mathematical content, recognize structure rather than only plain text.Example:Student writes:2x + 5 = 15System should understand:- Equation- Variable: x- Coefficient: 2- Constant: 5- Equality- Right side: 15If student writes:2x = 10x = 5the AI understands the relationship between the steps.---10. EQUATION STRUCTURESupport mathematical concepts such as:- Fractions- Exponents- Roots- Integrals- Derivatives- Matrices- Vectors- Trigonometric functions- Logarithms- Inequalities- Systems of equationsThe system should preserve mathematical meaning.---11. VOICE INPUTProvide a large, obvious:🎤 Speakbutton.When activated, the student can speak naturally.Do not require special commands.Example:«"I think photosynthesis happens because plants use sunlight to make food."»Convert this into a text object on the Board.---12. VOICE MUST FEEL LIKE THINKINGVoice input should not feel like dictating to a chatbot.The student should be able to speak while solving.Example:«"First I'm going to divide both sides by two..."»The system places the relevant transcription on the Board.The student can continue speaking.---13. VOICE SEGMENTATIONLong speech should be intelligently divided into meaningful Board objects when appropriate.For example:Student says:«"Photosynthesis uses sunlight. Plants take in carbon dioxide. They also use water. The plant then produces glucose and oxygen."»Instead of one giant paragraph, the system may create several logical blocks:Photosynthesis uses sunlight.Plants take in carbon dioxide.Plants use water.Glucose and oxygen are produced.Each can be moved independently.Do not split speech unnaturally.---14. SPEECH CORRECTIONSpeech-to-text can produce errors.The AI should use context to interpret likely intended meaning.Example:Speech recognition produces:«"Plants make close"»Context suggests:«"Plants make glucose."»The system should not immediately treat "close" as the student's actual concept.Where confidence is high, correct recognition internally.Where confidence is low, ask:«"Did you mean glucose?"»---15. MULTILINGUAL / MIXED LANGUAGE INPUTThe recognition system should support multilingual student input where the underlying AI supports the language.Especially support natural language mixing such as:«"Photosynthesis mein plant sunlight use karta hai."»or:«"Water leaf mein enter hota hai aur phir process start hota hai."»The AI should focus on the student's meaning.Do not penalize language mixing.---16. IMAGE INPUTAllow students to:- Upload an image- Take a photo- Drag and drop an imagePossible images:- Textbook questions- Homework- Worksheets- Handwritten questions- Diagrams- Graphs- Charts- Scientific illustrations- Mathematical problems- NotesThe AI should analyze the image and identify relevant content.---17. IMAGE QUESTION EXTRACTIONExample:Student uploads:A photograph of a textbook question.AI extracts:«"Explain the process of photosynthesis."»Then places the question on the Board.The original image should remain available.The student should be able to view both:Original QuestionandRecognized Question---18. IMAGE DIAGRAM UNDERSTANDINGIf a student uploads a diagram, the AI should attempt to identify:- Objects- Labels- Relationships- Arrows- Structures- Text- Graphs- Relevant conceptsExample:Student uploads a heart diagram.AI can identify:- Right atrium- Left atrium- Ventricles- Valves- Major vesselsThen ask the student to work with it.---19. IMAGE + BOARDUploaded images should become Board objects.Student can:- Move image- Resize image- Delete image- Annotate image- Draw over image- Add text beside it- Connect arrows to itThe AI understands these interactions as part of the learning session.---20. PASTE CONTENTAllow students to paste:- Text- Questions- Equations- NotesPasted content should become Board objects.The AI can analyze pasted content, but should distinguish between:Student-created reasoningandexternally pasted information.This distinction matters for learning analytics.---21. DRAWING INPUTStudents can draw freely.Drawings can represent:- diagrams- graphs- arrows- shapes- cycles- scientific structures- concept mapsThe AI should attempt to understand educational meaning where possible.---22. GRAPH RECOGNITIONFor mathematical/scientific graphs, identify:- axes- labels- points- lines- curves- direction- trendsExample:Student draws an increasing line.AI can recognize:«"Your graph shows a positive relationship."»---23. TABLE RECOGNITIONSupport tables.The AI should understand:- rows- columns- headings- values- relationshipsStudent can create or upload a table.---24. MIXED INPUTThe most important capability is allowing different input types simultaneously.Example:Student:- types a definition- draws a diagram- speaks an explanation- writes an equation- adds an arrowThe AI should treat the Board as one combined reasoning environment.---25. INPUT OWNERSHIPEvery object should be classified internally as:Student-createdCreated by the student.AI-createdGenerated by StepWise.ImportedUploaded/pasted from an external source.System-createdGenerated automatically by the application.This allows accurate learning analytics.---26. STUDENT THINKING VS AI CONTENTThe AI must never accidentally treat its own explanation as proof that the student understands something.Example:AI creates:«Photosynthesis requires carbon dioxide.»That does NOT mean:«Student understands carbon dioxide.»Only student actions/explanations should contribute to the student's demonstrated understanding.This is a critical rule.---27. RECOGNITION CONTEXTRecognition should consider context.For example, the handwritten word:«"cell"»could mean different things depending on the question.If the question is biology:«cell»If the question is prison:«cell»If the question is mathematics:«cell could refer to a spreadsheet cell.»The current question, subject, surrounding Board content, and previous student actions should help determine meaning.---28. SEMANTIC UNDERSTANDINGDo not stop at transcription.The recognition pipeline should be:Raw input↓Recognition↓Meaning extraction↓Concept identification↓Relationship identification↓Learning context↓AI reasoning engineExample:Student speaks:«"Plants eat sunlight."»Transcription:"Plants eat sunlight."Semantic interpretation:- Student associates plants with sunlight.- Student may understand sunlight is required.- "Eat" indicates an incorrect conceptual model.This distinction allows StepWise to teach rather than merely correct grammar.---29. PARTIAL SENTENCESStudents often think in fragments.Examples:«"because sunlight..."»«"water from roots..."»«"then oxygen..."»Do not automatically mark fragments as wrong.Determine whether the student is:- still thinking- writing a note- completing an idea- answering a questionWait for meaningful completion where appropriate.---30. REAL-TIME VS COMPLETION DETECTIONDo not analyze every keystroke.Do not interrupt every pen stroke.Do not interrupt while the student is speaking.Use intelligent completion detection.Possible signals:- pause- punctuation- sentence completion- mathematical expression completion- explicit submission- student tapping "Analyze"- meaningful object movement- end of speechThen evaluate.---31. STUDENT CAN MANUALLY SUBMITProvide an optional:✓ Check Thisbutton.The student can finish an idea and ask:«"Check this."»The AI analyzes the selected object or current response.This gives the student control.---32. SELECTIVE ANALYSISThe student can select:- one word- one text block- multiple objects- an equation- a diagram- the entire BoardThen choose:AnalyzeThe AI should adjust its analysis scope accordingly.---33. INPUT ERROR HANDLINGIf handwriting is unreadable:«"I couldn't read this clearly. Try writing it again or use the typing tool."»If voice is unclear:«"I didn't catch that. Try saying it again."»If image quality is poor:«"This image is difficult to read. Try taking a clearer photo."»If equation recognition is uncertain:«"I think this says 2x + 5 = 15. Is that right?"»Never fabricate recognition.---34. INPUT PRIVACYVoice recordings and uploaded images should be handled securely.Where possible:- Process temporarily- Store only what is necessary- Allow deletion- Clearly communicate storage behavior- Do not expose user data to other users---35. INPUT PERFORMANCEOptimize recognition so the student does not feel delayed.Use:- debouncing- asynchronous processing- incremental updates- local processing where available- caching- efficient API callsThe Board should remain interactive while recognition occurs.---36. OFFLINE / CONNECTION FAILUREIf AI services are temporarily unavailable:Do not lose student work.The student should still be able to:- write- type- draw- move objects- save the Board locally where possibleWhen connection returns, synchronize the Board and resume AI analysis.---37. INPUT ENGINE OUTPUTThe recognition system should produce structured information such as:Input type:handwritingRaw content:[original strokes]Recognized content:"Plants use sunlight"Confidence:0.94Semantic concepts:- plants- sunlight- food productionStudent-owned:trueTimestamp:[session timestamp]Board object:[object ID]For voice:Input type:voiceTranscript:"Plants use sunlight to make food."Confidence:0.97Concepts:- photosynthesis- sunlight- food productionStudent-owned:trueThis structured output will be consumed by the AI Understanding Engine.---38. FINAL RULEThe Input & Recognition Engine must remember:«Its job is not merely to convert handwriting to text or speech to text.»Its real purpose is:«To understand how the student is expressing their thinking.»The final pipeline should therefore be:TYPE / WRITE / SPEAK / DRAW / IMAGE↓RECOGNIZE↓UNDERSTAND↓EXTRACT CONCEPTS↓IDENTIFY RELATIONSHIPS↓PRESERVE STUDENT INTENT↓SEND STRUCTURED THINKING TO THE STEPWISE AI BRAINThis engine must make StepWise feel natural regardless of how the student chooses to think.
